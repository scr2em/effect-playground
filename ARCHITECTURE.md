# Architecture: static Astro site, everything runs in the browser

The playground is a static site. Type checking and execution of learner code happen in the
browser. There is no server. The build output in `dist/` is deployed to GitHub Pages at
`https://scr2em.github.io/effect-playground/` (Astro `base: "/effect-playground"`).

Two workstreams own disjoint directories and meet at the interfaces in this file.

| Owner | Directories / files |
|---|---|
| **UI** | `src/pages/`, `src/layouts/`, `src/components/`, `src/client/`, `src/styles/` |
| **Runtime** | `src/runtime/`, `scripts/build-effect-bundle.mjs`, `scripts/build-effect-types.mjs`, `scripts/verify.ts`, `scripts/console-shim.ts`, `lib/run.ts`, content fixes in `content/sections/*.ts` |
| Shared, do not edit without coordination | `package.json`, `astro.config.mjs`, `tsconfig.json`, `content/types.ts`, `content/index.ts` |

`content/sections/*.ts` stays the single source of truth for lessons. `scripts/verify.ts` keeps
verifying every lesson, challenge, and problem in Node.

## Directory layout

```
content/                     lesson data (unchanged), content/index.ts -> loadSections()
src/
  runtime/
    types.ts                 Diagnostic, RunResult, FullResult (shapes below)
    format.ts                console formatting shared by browser worker and Node verifier
    client.ts                getRunner(): Runner  (lazy singleton, spins up workers)
    editor.ts                createEditor(): Monaco editor factory used by the UI
    typecheck.*              TypeScript checking against bundled Effect types (worker)
    exec.worker.ts           runs transpiled learner code with the console shim, posts output
  client/
    code-runner.ts           <code-runner> custom element (editor + run/check/hints/solution)
    progress.ts              localStorage progress + drafts + editor heights
  components/                Astro components (server-rendered): Sidebar, SectionIntro,
                             LessonCard, DoDontTable, ChallengeCard, ProblemCard, RecallList,
                             Markdown (marked + shiki at build time), CodeRunner (emits the element)
  layouts/Base.astro
  pages/index.astro          redirects to the first section
  pages/[section]/index.astro  one page per section, getStaticPaths from loadSections()
  pages/scratch/index.astro  free editor
public/
  effect.js                  GENERATED by scripts/build-effect-bundle.mjs (esbuild, ESM, browser)
  effect-types.json          GENERATED by scripts/build-effect-types.mjs (virtual FS for type checking)
scripts/
  build-effect-bundle.mjs    bundles `export * from "effect"` -> public/effect.js
  build-effect-types.mjs     collects node_modules/effect/dist/**/*.d.ts + package.json
                             (+ TypeScript lib.*.d.ts if the runtime needs them) -> public/effect-types.json
  console-shim.ts            Node --import hook that installs src/runtime/format.ts on globalThis.console
  verify.ts                  runs every code block (node + tsx + console-shim), compares output
lib/run.ts                   Node runner used by verify.ts (typecheck via TS language service, execute via child process)
bin/effect-playground.js     `npx effect-playground`: serves dist/ on localhost and opens the browser
.github/workflows/deploy.yml builds and deploys dist/ to GitHub Pages on push to main
```

## Interface 1: result shapes (`src/runtime/types.ts`)

```ts
export interface Diagnostic { line: number; col: number; endLine: number; endCol: number; message: string }
export interface RunResult {
  stdout: string        // everything console.log/info/debug printed, joined with "\n" endings
  stderr: string        // console.error/warn output and uncaught error text
  exitCode: number | null   // 0 = finished with no uncaught error; 1 = uncaught error or rejection; null = killed
  timedOut: boolean
  durationMs: number
}
export interface FullResult extends RunResult { diagnostics: Array<Diagnostic> }
```
Line numbers are 1-based and refer to the learner's code exactly as typed (no preamble offsets).

## Interface 2: the runner (`src/runtime/client.ts`)

```ts
export interface Runner {
  ready: Promise<void>                       // resolves when types + bundle are loaded
  typecheck(code: string): Promise<Array<Diagnostic>>
  execute(code: string, timeoutMs?: number): Promise<RunResult>   // default 10_000
  check(code: string, timeoutMs?: number): Promise<FullResult>    // typecheck then execute, always both
}
export function getRunner(): Runner         // lazy singleton; safe to call many times
```
Rules:
- `check` never rejects for learner mistakes. Type errors go to `diagnostics`, runtime errors to
  `stderr` + `exitCode: 1`, infinite loops to `timedOut: true` (the worker is terminated and a
  fresh one is created for the next run).
- Learner code is a complete module that imports from `"effect"` (and possibly `"effect/testing"`).
  The runtime must resolve those imports to the bundled `public/effect.js` (build the bundle so
  that `effect/testing` is also reachable, e.g. as a second entry or a namespace export).
- Only one execution at a time per page; a second call while one runs waits for the first.
- `execute` installs the console shim from `format.ts` inside the worker before running code.

## Interface 3: the editor (`src/runtime/editor.ts`)

```ts
export interface EditorHandle {
  getValue(): string
  setValue(code: string): void
  setDiagnostics(d: Array<Diagnostic>): void   // shows markers in the gutter/squiggles
  onChange(cb: (code: string) => void): void
  focus(): void
  layout(): void
  dispose(): void
}
export function createEditor(container: HTMLElement, options: {
  code: string
  onRun?: () => void          // bound to Cmd/Ctrl+Enter
  readOnly?: boolean
}): Promise<EditorHandle>
```
Monaco is loaded from the `monaco-editor` npm package through Vite (no CDN). The theme is dark,
background `#0b0d12`, font size 13, no minimap, `automaticLayout: true`. The editor shows
TypeScript syntax highlighting. Semantic diagnostics come from `setDiagnostics` (the runtime),
not from Monaco's own worker, unless the Runtime owner decides Monaco's TS worker with
`addExtraLib` IS the type checker; either way the UI only calls `setDiagnostics`.

## Interface 4: console output format (`src/runtime/format.ts`)

The same formatter runs in the browser worker and in the Node verifier, so expected outputs are
runtime-independent. `format(args: unknown[]): string` joins formatted args with a single space.
- Top-level strings print as is; nested strings print with double quotes: `"x"`.
- `number`, `boolean`, `null`, `undefined`, `bigint` (`10n`), `symbol` (`Symbol(x)`) print like Node.
- Arrays: `[ 1, 2, 3 ]`, empty `[]`. Objects: `{ a: 1, b: "x" }`, empty `{}`. Class instances:
  `ClassName { a: 1 }`. Nesting deeper than 4 levels prints `[Object]` / `[Array]`.
- If the value has a method at `Symbol.for("nodejs.util.inspect.custom")`, call it with
  `(depth, options, inspect)` and format its return (string as is, otherwise recurse). Effect data
  types (Option, Result, Chunk, Cause, Exit, Duration...) implement this, so they print as Node
  prints them.
- `Error` instances print `Name: message` (no stack). Map: `Map(1) { "a" => 1 }`, Set: `Set(2) { 1, 2 }`.
- Single line when the result is 72 characters or fewer; otherwise break at the top-level
  container with 2-space indentation, one entry per line (Node style, no trailing commas).
- `console.log/info/debug` -> stdout, `console.error/warn` -> stderr, `console.table` ->
  stdout via `format`. Each call appends one line.

## Interface 5: page and item addressing

- Section URL: `/effect-playground/<sectionId>/`. Items: `#<itemId>` (lesson, challenge, problem
  ids from content), plus `#learn`, `#do-dont`, `#fix-it`, `#build-it`, `#recall`, `#recall-N`.
- Every heading has a `#` anchor link that copies the absolute URL to the clipboard.
- The `<code-runner>` element receives attributes: `data-id`, `data-kind` (`lesson|challenge|problem|scratch`),
  and children `<script type="text/plain" data-role="code">`, optional `data-role="solution"`,
  `data-role="expected"`, `data-role="hints"` (JSON array), `data-role="explanation"` (HTML).
  Progress key: `effect-playground:done` (object of id -> timestamp), drafts
  `effect-playground:draft:<id>`, heights `effect-playground:height:<id>`.

## Toolchain

pnpm is the package manager (`packageManager` in package.json, `pnpm-lock.yaml` committed).
`typescript` (7.x, native) provides `tsc` for `pnpm run typecheck`. The JavaScript TypeScript API used
by `src/runtime/typecheck-core.ts`, `src/runtime/transpile.ts`, the typecheck worker, and `lib/run.ts`
is imported from the alias package `typescript-js` (`npm:typescript@6.0.3`). Never import the API from
`typescript` in those files: TypeScript 7 has no JavaScript API.

## Build and verify

```
pnpm run build    # bundle effect -> public/effect.js, types -> public/effect-types.json, astro build -> dist/
pnpm dev          # astro dev with the generated assets (run the two build scripts once first)
pnpm run verify   # node --import tsx --import ./scripts/console-shim.ts, every code block, must be 100%
```
`public/effect.js` and `public/effect-types.json` are gitignored and rebuilt in CI.

## Styling: StyleX

All styling uses StyleX (`@stylexjs/stylex` 0.19, compiled by `@stylexjs/unplugin/vite`, already
wired in `astro.config.mjs`). No hand-written `.css` files except a tiny reset. Conventions:
- Design tokens in `src/styles/tokens.stylex.ts` via `stylex.defineVars` (colors, fonts, radii).
- Component styles in `src/styles/<name>.stylex.ts` with `stylex.create`; apply in `.astro`
  templates and in custom-element code with `stylex.props(styles.x, cond && styles.y)`, spreading
  the returned `{ className, style }`.
- Monaco's own CSS (`monaco-editor/min/vs/editor/editor.main.css` or the ESM equivalent) is the one
  third-party stylesheet and is imported by `src/runtime/editor.ts`.
- In dev, the layout must include the StyleX dev CSS link and runtime shim documented by the
  unplugin README (`/virtual:stylex.css` when `import.meta.env.DEV`); in production the plugin emits
  a CSS asset that Astro links automatically.

## Interactive components: React islands

The interactive playground widget is a React component (`src/client/CodeRunner.tsx`) rendered by
Astro as an island (`<CodeRunner client:visible {...props} />` from `src/components/CodeRunner.astro`).
React 19 with `@astrojs/react` is wired in `astro.config.mjs`. Props carry `id`, `kind`, `code`,
`solution`, `solutionHtml`, `expected`, `hints`, `explanationHtml`, `tall`. A `<pre>` with the code
is rendered as the server fallback so the page is readable before hydration. Small interactive bits
outside the widget (sidebar progress badges, reset progress, mobile toggle, anchors) may stay as
plain TypeScript in `src/client/app.ts` or become React islands; either is acceptable.
StyleX applies to React components with `{...stylex.props(styles.x)}`.

## Non-goals

No server. Content authoring format stays TypeScript data.
